# 踩坑与经验

## 抓取
- **浏览器自动化要用装了扩展的那个浏览器**（本例是 Chrome）。用系统默认浏览器打开登录页，用户登在了别的浏览器里，白登一轮。
- 某招聘平台的搜索接口**连续翻到第4页左右会返回"环境异常"（风控）**，之后同一会话的接口全部失败。要放慢（每页间隔3–6秒随机），隔天再抓。
- 某平台搜索页的数据放在前端状态里（Vue store），**滚动加载会累积**；`?p=2` 之类的翻页参数无效。
- 另一平台是服务端渲染，`currentPage=0,1,2` 翻页，直接解析页面 DOM。
- **多文件下载会被 Chrome 拦**：本机起一个只监听 `127.0.0.1` 的小接收器（`scripts/local_receiver.py`），页面把数据 POST 过来存盘。每个网站第一次需要在 Chrome 里点一次"允许访问本地网络"。
- **工商信息网站的搜索接口返回的数据是混淆过的**（同一公司两次查询的注册资本、成立年份都不一样），不能用；要用**页面渲染出来的内容**。
- 遇到验证码**不要绕过**，让用户自己完成，并放慢请求速度避免再触发。
- 不要替用户登录任何账号；需要登录的网站让用户自己扫码。

## 数据与评分
- 抓取只是**抽样**（每个关键词前几页），不是该城市的全部岗位，要在文档里写明。
- "经验不限"不可信；大厂写"不限"也会筛经验。
- 游戏方向的岗位里混有大量**美术/特效/策划**，程序和美术要分开。
- **实习岗对已毕业的人大多不开放**（"在读/27届"），投之前先问HR；**不要为了通过而写"在读"**，学信网一查就穿帮。
- 评分高的往往是大厂，但无经验者进不去；把权重往"录取可能性"倾斜。

## 工程
- `python -I`（隔离模式）会忽略 `PYTHONIOENCODING`，脚本里自己 `sys.stdout.reconfigure(encoding='utf-8')`。
- pandas 新版 `to_excel` 的 `sheet_name` 必须写成关键字参数。
- Excel/Word 正打开着时，同名文件写不进去（`PermissionError`），另存成带版本号的新文件。
- 让并行的工作（查资料、写脚本）交给子 Agent，主线专注决策和需要用户浏览器的事。

## 底线
- **不编造经历**。简历每一条都要求求职者自己能讲10分钟；各版本之间只调整重点和顺序，事实来自同一份数据。
- 批量投递做成**半自动**（生成清单、话术和跟踪表，"发送"由本人点），平台一般禁止脚本自动投递，会封号。
